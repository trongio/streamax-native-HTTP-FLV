streamax-native

Native iOS, Android, Windows and Linux players for Streamax dashcam HTTP-FLV streams. One Rust core, hardware decoders everywhere, no WebAssembly.

Library API Build steps How it works
The problem

Browsers can't play these streams.
Native platforms can.

The Streamax web client ships a 3.7 MB minified WebAssembly bundle that decodes HEVC in software because <video> tags can't handle the format.

iOS, Android and Windows all have hardware HEVC decoders. The only blocker is that the FLV variant these cameras emit uses codec_id = 12 directly — a non-standard Chinese-vendor convention that mainline FFmpeg and libVLC reject or crash on.

Solve that single demux problem and the rest is free.

terminal — without this library 
$ mpv 'https://camera.../live.flv?...'
[ffmpeg/demuxer] flv: Video codec (c) is not
implemented. Update your FFmpeg version...

$ vlc 'https://camera.../live.flv?...'
zsh: segmentation fault (core dumped)  vlc

$ ffprobe 'https://camera.../live.flv?...'
zsh: segmentation fault (core dumped)  ffprobe
Architecture

One core, four targets

🦀

streamax-core

Rust crate, ~600 LOC. Compiles to a static lib (iOS), shared lib (Android, Linux), or DLL (Windows).

Using the library

No host, no devid, no secrets in the binary

Caller passes every variable part at runtime. The library exposes two entry points: stream(...) takes the URL's components, play(url:) takes a pre-built URL. Both route through the same demuxer. Pinning is opt-in.

streamComponent API — when your backend returns fields as JSON
let player = StreamaxPlayer()

// Optional — defense-in-depth pinning. Empty by default = system CA only.
player.pinnedSPKIHashes = ["base64-sha256-of-your-server-spki="]

let creds = try await api.fetchCameraCredentials(imei: vehicle.imei)

player.stream(
    host: creds.host,
    port: 22060,
    uuid: creds.uuid,
    channel: selectedCamera,
    audio: true,
    quality: connectionIsCellular ? .sub : .main,
    expires: creds.expires,
    hash: creds.hash
)
playURL escape hatch — when the backend hands you a signed URL
let response = try await api.getStreamURL(imei: vehicle.imei)
// response.url = "https://host:port/live.flv?devid=X&expires=Y&hash=Z"

player.play(url: URL(string: response.url)!)
streamComponent API
val player = StreamaxPlayer()

// Optional pinning
player.certificatePinner = CertificatePinner.Builder()
    .add(creds.host, "sha256/${'$'}{creds.spkiHashBase64}")
    .build()

val creds = api.fetchCameraCredentials(vehicle.imei)

player.stream(
    host = creds.host,
    port = 22060,
    uuid = creds.uuid,
    channel = selectedCamera,
    audio = true,
    quality = StreamaxPlayer.Quality.MAIN,
    expires = creds.expires,
    hash = creds.hash,
)
playURL escape hatch
val response = api.getStreamURL(vehicle.imei)
player.play(response.url)
streamComponent API
var player = new StreamaxPlayer(libVlc)
{
    // Optional pinning
    PinnedSpkiHashesBase64 = new[] { "base64-sha256-of-your-server-spki=" },
};

var creds = await api.FetchCameraCredentialsAsync(vehicle.Imei);

await player.StreamAsync(
    host:    creds.Host,
    uuid:    creds.Uuid,
    port:    22060,
    channel: selectedCamera,
    audio:   true,
    quality: StreamaxPlayer.Quality.Main,
    expires: creds.Expires,
    hash:    creds.Hash);
playURL escape hatch
var response = await api.GetStreamUrlAsync(vehicle.Imei);
await player.PlayAsync(response.Url);
Optional fields. Pass expires: 0 and hash: "" to omit them from the constructed URL — useful while a camera server transitions to validating signed URLs.
Quick start

Pick your platform

Each build produces one artifact. Drop it into the matching platform project and you're done.

1Build the Rust core + both smoke-test binaries
cd core
cargo build --release --examples
2aVideo + audio via MPEG-TS multiplex (recommended)
curl -skN 'https://<camera-host>:<port>/live.flv?devid=...&hash=anything' \
  | target/release/examples/flv_to_ts \
  | mpv --profile=low-latency -
2bVideo only (raw HEVC Annex-B)
curl -skN 'https://<camera-host>:<port>/live.flv?devid=...&hash=anything' \
  | target/release/examples/flv_to_annex_b \
  | mpv --demuxer=lavf --demuxer-lavf-format=hevc --profile=low-latency -
Expected stderr output
VideoConfig: 352x288, 74 bytes
AudioConfig: 8000Hz 1ch (object_type=2)
done: 1 video cfg, 47 frames, 1 audio cfg, 35 audio frames
1On a Mac with Xcode installed
cd core
./build.sh ios
# → target/StreamaxCore.xcframework
2Create a new SwiftUI iOS project. Drag in:
  • • StreamaxCore.xcframework  (Embed & Sign)
  • • ios/*.swift  (4 files)
  • • ios/StreamaxCore-Bridging-Header.h  (set as Bridging Header)
3Merge Info.plist.snippet.xml into your Info.plist. Build & run.
1Install cargo-ndk and point at your NDK
cargo install cargo-ndk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/26.1.10909125

cd core
./build.sh android
# → target/android-jniLibs/{arm64-v8a,armeabi-v7a,x86_64,x86}/libstreamax_core.so
2Copy the .so files into the Android project
cp -r core/target/android-jniLibs/* android/app/src/main/jniLibs/
3Open android/ in Android Studio. The CMake build for the JNI bridge runs automatically.
1Cross-compile from any host or build natively on Windows
cd core
./build.sh windows
# → target/x86_64-pc-windows-gnu/release/streamax_core.dll
2Copy the DLL next to the .csproj and add it to the project
cp core/target/x86_64-pc-windows-gnu/release/streamax_core.dll windows/
3Open StreamaxDemo.csproj in Visual Studio / Rider. NuGet pulls LibVLCSharp automatically.
Production status

What's ready, what isn't

Feature iOS Android Windows

Windows multi-camera grid and PiP are gated on WPF + libVLC ergonomics, not the core — single-camera audio + video works end-to-end through the MPEG-TS pipeline.

Discovered along the way

Two things worth knowing

Both are out-of-scope for this repo but show up while building it. File them on the relevant backlog.

Patched

The URL hash was fake

streamax_stream.php generated a meaningless random string as the URL signature:

// before
$hash = generateRandomString(rand(20, 200));

// after — HMAC + TTL, see docs/backend-hmac.md
$hash = hash_hmac("sha256", $payload, $secret);

PHP side is now signing properly; camera server validation is the next step — design notes in backend-hmac.md.

Upstream

Mainline FFmpeg 7.x still crashes

Tested with the johnvansickle.com static FFmpeg 7.0.2 build:

$ ffprobe 'https://camera.../live.flv?...'
zsh: segmentation fault (core dumped)
ffprobe -v info 'https://...'

The "enhanced RTMP" patches added codec ID 12 via FOURCC method; the Chinese-vendor direct-codec-12 encoding still segfaults. That's why we need our own demuxer.
